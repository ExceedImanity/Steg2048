About Steg2048

100% browser-based

Steg2048 is a steganography experiment: instead of storing text directly, the application encrypts the message and turns the resulting bits into possible choices along a valid 2048 trajectory.

The result is a JSON file containing only a sequence of boards. The password is never included in that file.

How does it work?

At each step, the engine chooses a valid 2048 move. The encrypted bits then select one possible position for the new tile. The decoder replays the exact same logic to recover the bits.

Encryption

The browser derives a key from the password with PBKDF2-SHA-256 (250,000 iterations), a random 16-byte salt and a 256-bit AES key.

AES-GCM encrypts the message and authenticates its integrity. A wrong password or a modified trajectory must make decryption fail.

Privacy

This version has no backend. Encoding, decoding and board generation use only JavaScript and the browser Web Crypto API.

The site can be served by GitHub Pages, but your message and password are not sent to GitHub during encryption or decryption.

Format

The current format is steg2048-web-v1. The exported JSON contains the format name and the ordered list of boards.

Current limit: 96 UTF-8 bytes per message and a password of at least 8 characters.

Limitations

Encryption protects the content; steganography only aims to make the transport less obvious. Steg2048 does not promise that a trajectory is undetectable or that it perfectly resembles a human game.

For genuinely sensitive data, treat this project as an educational experiment, not as an audited security protocol.

Why GitHub Pages?

Because everything is static: index.html, CSS and JavaScript modules. There is no Flask, no Python to install and no application server to maintain. Once the repository is published with Pages, anyone can open the URL and use the tool.

No backend. No telemetry. No runtime dependencies. The project stays focused on one idea: encrypt a small message and transport it through a valid 2048 trajectory.
